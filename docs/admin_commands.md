# Справочник команд администрирования (CRM)

Все команды ниже доступны только в супергруппе поддержки (`SUPPORT_CHAT_ID`) для пользователей из `ADMIN_IDS`.

> [!NOTE]
> Если `ADMIN_IDS` не задан (пустой), права оператора получают все участники супергруппы поддержки (при старте выводится предупреждение в `stderr`).

---

## 1. Управление жизненным циклом обращения (внутри топика)

| Команда / Синтаксис | Область | Описание и комментарии |
| :--- | :--- | :--- |
| `/end` | Внутри топика | Закрывает текущее активное обращение и сам топик (`🔴` + `close_forum_topic`). Убирает кнопки с шапки, уведомляет топик и отправляет клиенту сообщение с кнопкой «Переоткрыть обращение» и оценкой CSAT (`1–5⭐`). Идемпотентна. |
| `/take` | Внутри топика | Назначает активный тикет на отправившего команду оператора (`assigned_operator_id`). Если тикет был в статусе `new`, переводит его в `in_progress` (`🟡`). |
| `/assign <user_id>` | Внутри топика | Передаёт активный тикет другому оператору по его Telegram `user_id`. Также работает без аргумента, если отправить команду **ответом (reply)** на сообщение нужного оператора в топике. |
| `/waiting` | Внутри топика | Переводит активный тикет в статус `waiting_user` (`🔵` — ожидание ответа клиента). При следующем сообщении от клиента статус автоматически вернётся в `in_progress` (`🟡`). |
| `!<текст>` | Внутри топика | **Внутренняя заметка (Whisper).** Любое сообщение (или подпись к медиа), начинающееся с `!`, **не пересылается клиенту** и остаётся только внутри топика для обсуждения между операторами. Редактирование таких сообщений также не уходит клиенту. |

---

## 2. Карточка клиента, теги и модерация (внутри топика)

| Команда / Синтаксис | Область | Описание и комментарии |
| :--- | :--- | :--- |
| `/info` | Внутри топика | Выводит сводку по клиенту: Telegram ID, username, имя, статус бана, общее число обращений, постоянную заметку, а также данные последнего/активного тикета (№, статус, оператор, теги, `source_payload` из `/start`, CSAT). |
| `/note <текст>` | Внутри топика | Сохраняет постоянную CRM-заметку о клиенте (отображается в `/info` и в новой шапке при переоткрытии). Вызов `/note` без текста показывает текущую заметку; `/note clear` — очищает её. Не пересылается клиенту. |
| `/tag <теги>` | Внутри топика | Назначает теги на активный тикет через запятую или пробел (например: `/tag billing, vip` или `/tag #bug`). Теги нормализуются в нижний регистр без `#`. `/tag clear` — очищает теги. |
| `/ban [причина]` | Внутри топика | Блокирует клиента (`is_banned=True`), сохраняет причину и автоматически закрывает активный тикет и топик. Все последующие сообщения и попытки переоткрытия от заблокированного клиента игнорируются. |
| `/unban` | Внутри топика | Снимает блокировку с клиента (`is_banned=False`, очищает `ban_reason`), позволяя ему снова писать в поддержку. |

## 3. Быстрые ответы / Макросы

| Команда / Синтаксис | Область | Описание и комментарии |
| :--- | :--- | :--- |
| `/r <slug>` | Внутри топика | Отправляет клиенту сохранённый шаблон ответа с указанным `slug`. Работает только в открытом обращении; обновляет `first_response_at`, назначает оператора (если не назначен) и переводит тикет `new -> in_progress`. |
| `/macros` | Любой топик группы | Выводит список всех сохранённых шаблонов (`slug` и превью текста). |
| `/macro_add <slug> <текст>` | Любой топик группы | Создаёт новый шаблон или обновляет текст существующего шаблона с ключом `<slug>` (приводится к нижнему регистру). |
| `/macro_del <slug>` | Любой топик группы | Удаляет шаблон с указанным `slug`. |

## 4. Массовые операции и аналитика (в группе поддержки)

| Команда / Синтаксис | Область | Описание и комментарии |
| :--- | :--- | :--- |
| `/all_end` | Любой топик группы | Массово закрывает **все** открытые обращения (`FOR UPDATE SKIP LOCKED`), переименовывает и закрывает их топики, а уведомления клиентам отправляет в фоновой задаче с троттлингом (без блокировки webhook). Возвращает число закрытых и переименованных топиков. |
| `/stats` | Любой топик группы | Показывает общую статистику CRM: всего тикетов, распределение по статусам (`new`, `in_progress`, `waiting_user`, `closed`), среднее время первого ответа (FRT в секундах), средний CSAT и количество заблокированных клиентов. |

## 5. Inline-кнопки и синхронизация с интерфейсом Telegram

- **Кнопка `Взять в работу` (в шапке топика):** назначает тикет на нажавшего оператора и убирает кнопку взятия, оставляя `Закрыть обращение`.
- **Кнопка `Закрыть обращение` (в шапке топика):** привязана к конкретному `ticket_id`. При нажатии на устаревшую кнопку от прошлого обращения она удаляется с предупреждением «Кнопка устарела: обращение уже закрыто».
- **Штатное закрытие/переоткрытие топика в Telegram UI:** события `forum_topic_closed` и `forum_topic_reopened` автоматически синхронизируются с БД (обновляют статус, префикс топика и уведомляют клиента при закрытии).

---

## 6. Права операторов

- Оператор — участник супергруппы поддержки, чей Telegram ID указан в `ADMIN_IDS` (через запятую). Пустой `ADMIN_IDS` разрешает команды всем участникам группы, при старте бот выводит предупреждение в `stderr`.
- Кнопки «Взять в работу» и «Закрыть обращение» проверяют и ID, и чат. При отказе бот выводит ID нажавшего и причину: «У вашего ID 123456789 нет необходимых разрешений. Добавьте этот ID в ADMIN_IDS в .env и перезапустите бота.» либо «Кнопка нажата в чате …, а в SUPPORT_CHAT_ID указан …». Причина также пишется в лог с пометкой `denied`.
- После правки `ADMIN_IDS` нужен перезапуск бота: `.env` читается один раз при старте.

## 7. Индикация статусов в названии топика

- `🟢` — новое обращение (`new` / `open`), оператор ещё не ответил.
- `🟡` — в работе (`in_progress`), оператор ответил или взял тикет в работу.
- `🔵` — ожидание клиента (`waiting_user`), задано командой `/waiting`.
- `🔴` — обращение закрыто (`closed`), топик закрыт.
