# Шаблоны сообщений поддержки SEX SCREENER

Единый источник текстов — `config/messages.json`. Код читает его через `config/messages.py` (`msg(key, **kwargs)`); файл кешируется на процесс (`lru_cache`), после правки нужен рестарт бота.

Стиль: деловой, без разговорных оборотов и эмодзи в клиентских текстах. Ссылки, IP-адреса и код доступа в шаблонах не упоминаются: доступ ищется по логину или ID аккаунта, код доступа сообщать запрещено.

## Секции конфига

| Ключ | Где используется | Плейсхолдеры |
| :--- | :--- | :--- |
| `brand_name` | справочно, для будущих текстов | — |
| `welcome_text` | приветствие в `/start` и при переоткрытии обращения | `{mention}`: `, @логин` или `!`, если username нет |
| `ticket_closed_topic` | сообщение в топик после закрытия | — |
| `ticket_closed_user` | клиенту после закрытия + inline-кнопки «Переоткрыть» и CSAT | — |
| `ticket_closed_not_found` | клиенту по `/end` без активного обращения | — |
| `rate_limit_exceeded` | ответ на флуд | — |
| `delivery_failed_user` | не удалось скопировать сообщение в топик | — |
| `user_reopened_topic` | уведомление операторам о переоткрытии | — |
| `user_closed_topic` | уведомление операторам о `/end` | — |
| `operator_closed_reply` | оператор пишет в закрытое обращение | — |
| `user_blocked_bot` | клиент заблокировал бота | — |
| `operator_took_ticket` | сообщение в топик при взятии обращения в работу | `{name}`, `{login}`, `{user_id}` |
| `reaction_delivered` | реакция на сообщение клиента после доставки в топик | — |
| `reaction_csat` | реакция на сообщение с оценкой после CSAT | — |
| `csat_received` | уведомление в топик об оценке клиента | `{score}`, `{ticket_id}`, `{name}`, `{login}`, `{user_id}` |
| `csat_thanks` | уведомление после оценки | `{score}` |
| `csat_already_rated` / `csat_not_found` | ошибки CSAT (пока захардкожены в хендлере) | — |
| `buttons.*` | inline-кнопки шапки и сообщения о закрытии | — |
| `topic_status_prefixes` | префиксы названия топика по статусу тикета | — |
| `topic_header_footer` | подвал шапки топика | — |
| `quick_replies_seed` | заготовки для `/macro_add`, кодом не читается | — |

`msg()` вызывает `str.format`, поэтому в шаблонах без плейсхолдеров литеральные фигурные скобки недопустимы.

## Приветствие: что требуется от клиента

Одна короткая инструкция без вступления: логин или ID аккаунта, краткое описание вопроса/проблемы/предложения, просьба сразу уточнить детали. Код доступа для поиска не нужен и запрашивать его нельзя.

## Быстрые ответы операторам

`quick_replies_seed` — пять макросов под типовые обращения: `access`, `sub`, `pc`, `keys`, `signals`. Макросы хранятся в БД, поэтому их нужно один раз залить:

```
/macro_add access <текст из quick_replies_seed.access>
/macro_add sub <...>
```

Отправка клиенту — `/r <slug>`. Тексты макросов не содержат ссылок, IP и кода доступа.

## Что осталось захардкожено

Сообщения операторам внутри топика (`/take`, `/assign`, `/tag`, `/note`, `/ban`, `/stats`, `/macros`, ответы callback-кнопок) остаются в `bot/handlers.py`. Вынос — отдельным шагом: около 30 ключей, на клиентский опыт не влияют.
